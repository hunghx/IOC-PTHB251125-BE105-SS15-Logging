Phần 1

Tổng Quan Về Logging

1.1 - 1.2

Logging là gì?

Logging là quá trình ghi lại các sự kiện diễn ra trong quá trình hệ thống hoạt động. Lưu giữ thông tin thời gian, thành phần thực hiện, dữ liệu liên quan và nguyên nhân gây lỗi.

2026-09-16 10:30:15 INFO User 1001 login successfully
Log chuẩn mẫu

4 Lí Do Hệ Thống Không Thể Thiếu Logging:

1 Theo Dõi Hoạt Động (Monitoring)

Xác nhận các service khởi tạo thành công, hệ thống hoạt động bình thường.

INFO: Application started successfully
INFO: Database connected to PostgreSQL
2 Phân Tích & Xử Lý Lỗi (Debugging)

Xác định ngay nguyên nhân sự cố mà không cần mơ hồ đoán mò.

ERROR PaymentService: OrderId=10001 - Database connection timeout
3 Kiểm Tra Lịch Sử (Audit & Security)

Lưu lại vết thao tác quan trọng để điều tra hành vi người dùng & sự cố bảo mật.

INFO AdminAudit: Admin id=5 deleted product id=100
4 Đánh Giá Hiệu Năng (Performance)

Đo lường thời gian phản hồi (response time), phát hiện API hoặc DB chậm.

WARN PerformanceAspect: GET /products response time: 3500ms
Phần 2

Log Level & Cấp Độ Nghiêm Trọng

2.1 - 2.7
Mức độ quan trọng (Tăng dần)
💡 Cấu hình Production: Thường bật INFO + WARN + ERROR
INFO LEVEL Mặc định Production

Ghi lại các sự kiện hoạt động bình thường của ứng dụng như đăng nhập thành công, tạo dữ liệu mới, khởi động service.

Ví dụ Code Java:
log.info("User {} created successfully with ID {}", username, userId);
Trường hợp áp dụng:
  • Khởi tạo Bean / Application started.
  • Tạo dữ liệu thành công (User, Order, Payment).
  • Bắt đầu hoặc hoàn thành Batch Job.
* Click vào từng cấp độ bên trái để khám phá cách dùng chuẩn.

SLF4J, Lombok `@Slf4j` & Log Simulator

3.1 - 3.5

1. Khởi Tạo Logger Thủ Công Thuần Java 

@Service
public class UserService {
    private static final Logger log = 
        LoggerFactory.getLogger(UserService.class);

    public void createUser() {
        log.info("Create user");
    }
}

2. Dùng Lombok `@Slf4j` Khuyên Dùng 

@Slf4j // Tự động sinhLogger 'log'
@Service
public class UserService {

    public void createUser() {
        log.info("Create user");
    }
}

Phần 4

Cấu Hình Logging Trong Spring Boot

4.1 - 4.4

Cấu hình chuẩn trong application.properties

# 1. Level toàn cục & cấp package
logging.level.root=INFO
logging.level.com.example.service=DEBUG

# 2. Xuất Log ra File
logging.file.name=logs/application.log
logging.logback.rollingpolicy.max-file-size=10MB

# 3. Định dạng Pattern Console
logging.pattern.console=%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n
%d{...} Thời gian chi tiết
%-5level Mức Log căn lề 5 ký tự
%logger{36} Tên Class thực hiện log
%msg%n Nội dung & xuống dòng

File cấu hình nâng cao: logback-spring.xml

<configuration>
    <appender name="Console" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss} %highlight(%-5level) %cyan(%logger{36}) : %msg%n</pattern>
        </encoder>
    </appender>

    <root level="INFO">
        <appender-ref ref="Console" 
    </root>
</configuration>
Phần 5

Logging Trong Exception Handling

5.1 - 5.4
1. Logging Lỗi Sai (Mất Stack Trace) 
catch (Exception e) {
    log.error("Error creating user"); // MẤT DẤU VẾT!
}

⚠️ Không hề biết lỗi do đâu, dòng nào trong file Java bị NullPointer hay SQLException!

2. Logging Lỗi Đúng (Bảo Toàn Stack Trace) 
catch (Exception e) {
    log.error("Cannot create user {}", email, e);
}

✅ Truyền đối tượng e ở vị trí tham số cuối. SLF4J tự động in đầy đủ Stack Trace lỗi!

3. Quản Lý Lỗi Tập Trung Với @RestControllerAdvice

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public ResponseEntity<?> handleSystemError(Exception e, HttpServletRequest req) {
        log.error("System error on API: {} {}", req.getMethod(), req.getRequestURI(), e);
        return ResponseEntity.status(500).build();
    }
}

Structured Logging & Microservices Tracing

6.1 - 6.4

Log Truyền Thống (Plain Text)

  "level": "INFO",

Phần 7

3 Nguyên Tắc Logging Trên Production

7.1 - 7.3
1

Không Log Thông Tin Nhạy Cảm

Tuyệt đối không ghi: Password, Token JWT, Số thẻ ngân hàng, PIN vào log file.

❌ log.info("Pass: {}", password);
✅ log.info("User {} authenticated", id);
2

Log Phải Có Bối Cảnh (Context)

Ghi nhận đầy đủ OrderId, UserId, API path để khi tra cứu lỗi là hiểu ngay vấn đề.

❌ log.error("Database error");
✅ log.error("Order failed. OrderId={}, UserId={}", oId, uId);
3

Không Lạm Dụng Log Rác

Tránh log mọi dòng code. Gây tốn ổ cứng, giảm hiệu năng I/O của ứng dụng.

💡 Dùng DEBUG ở môi trường Dev. Chỉ bật INFO+ trên Production.

Yêu Cầu Bài Tập: Triển Khai Logging Cho User Service

1. REST API
  • POST /users (Tạo user)
  • GET /users/{id} (Xem chi tiết)
2. Log Level Matrix
  • Tạo thành công ➔ INFO
  • Không thấy user ➔ WARN
  • Lỗi DB ➔ ERROR
3. Application Config
  • logging.level.root=INFO
  • logging.level.service=DEBUG
Code Mẫu Gợi Ý: UserService.java 
@Slf4j
@Service
public class UserService {

    public UserResponse createUser(CreateUserRequest request) {
        log.debug("Finding existing user: {}", request.getUsername());
        
        if (repository.existsByUsername(request.getUsername())) {
            log.warn("Username {} already exists", request.getUsername());
            throw new DuplicateUserException("User existed");
        }

        User user = repository.save(request.toEntity());
        log.info("User {} created with ID: {}", user.getUsername(), user.getId());
        return UserResponse.from(user);
    }
}
